## Final Report

### 專案說明
<!-- 完整描述你的專案做了什麼 -->
本專案旨在透過及時單主機多人論壇的實作，讓我能夠回顧、統整電腦網路課程學習的 TCP, socket 知識，並實際運用在生活之中。
因此，本專案以能夠理解程式碼邏輯為目標，整體程式碼限縮在小於 150 行。內容分為 server 與 client 兩部分。

Server 能夠自動獲取當前主機的內網 IP 並進行綁定。它利用 TCP Socket 建立監聽，當擷取到新裝置加入時，便會動態建立獨立的子執行緒進行一對一維護，並將連線存入全域字典名冊中。當收到某個 Client 傳來的文字訊息時，Server 會 broadcast 遍歷名冊，將訊息以 UTF-8 編碼轉為二進位位元組，群發轉發給其餘所有在線使用者。此外，程式內建例外處理機制，不論是收到離線宣告或遭遇異常斷線，皆能主動釋放底層 Socket 資源，將斷線的 client 從字典中剔除，防止資源洩漏。

Client 則負責提供即時的多工互動介面。初始化時，它必須手動對齊並填入 Server 當前的區域網路 IP 以建立 TCP 三向交握連線。為了在終端機內同時處理輸入與輸出，Client 採用了多執行緒架構：主執行緒負責發送端，卡在輸入指令以等待使用者鍵入訊息，隨後計算長度、封裝 HEADER 並傳輸資料；與此同時，背景啟動的接收執行緒則獨立運作，無限迴圈卡在接收指令上，只要 Server 有轉發新訊息便能立刻同步重新整理在畫面上，確保使用者在輸入時聊天畫面不被阻斷。當使用者輸入結束指令時，Client 便會發送離線訊號並掛斷連線。

整體的效果為多視窗可以同時發言，並且會廣播到所有終端機，形成類似多人論壇的效果。

此程式碼我比較了兩種不同資料儲存邏輯，分別是:多執行緒(Multi-threading)與多路復用(I/O Multiplexing)。

多執行緒是對每個 client 都生成一個 thread ，優點是能避免阻塞(blocking)問題而同時處理多個 client 。缺點是它的空間複雜度是 O(N) ，當 client 人數到達一定程度，花在切換 threads 的時間會過多，並且記憶體會有被塞爆的風險。

多路復用不同於多執行緒，他同時只有一個 thread ，空間複雜度降至O(1)，面對少量與多量 client 可以保持相同效率。缺點是容易受阻塞影響。



### 使用方式
<!-- 如何編譯、執行、使用你的程式 -->
在單一主機上執行 server 執行檔，確認終端機有出現 STARTING 與 LISTENING 字樣。而後，更改 client 程式碼檔案裡的 SERVER 變數(更改為 server 的 IP 地址)，在終端機執行 client ，當看到"--- 已成功進入聊天室，請輸入訊息 (輸入 q 離開) ---"就可以輸入訊息，訊息會在所有 client 之間傳播。

### 與課程的關聯總結
<!-- 總結你的專題與進階程式設計及資料結構課程之間的關聯 -->
本專案實作與電腦網路、進階程式設計以及資料結構課程有著密不可分的深層關聯，主要體現在以下三個核心維度：
1. 電腦網路：傳輸層控制與應用層協議設計專案完整應用了 TCP 協議的可靠傳輸特性。藉由 Socket 程式設計管理端到端的連線狀態，並針對網路串流傳輸中常見的「黏包與拆包」問題，自行設計了固定長度（64 位元組）的 HEADER 封裝機制。這項設計確保了應用層文字資料在傳輸時，能精準被解碼與重組，加深了對網路分層架構與封裝概念的實務理解。
2. 進階程式設計：並行運算與多工調度策略在多工處理上，專案深入探討了作業系統底層兩種截然不同的並行（Concurrency）調度演算法，並進行了系統級的效率分析：多執行緒（Multi-threading）架構：採用「分治法」思維，為每個 Client 配置獨立的 Thread。其阻塞（Blocking）特性雖然直覺且能完美相容兩階段資料傳輸，但空間複雜度高達 $O(N)$。當連線人數暴增時，系統會因執行緒堆疊塞爆記憶體，CPU 也會因頻繁切換執行緒（Context Switch）而大幅浪費效能，這正是網路開發中經典的硬體瓶頸。I/O 多路復用（I/O Multiplexing）演算法：透過事件驅動與非同步輪詢機制，將所有 Socket 監聽收攏至單一執行緒中。此策略將空間複雜度優化至常數級別的 $O(1)$，不論人數多寡都能維持極低的資源消耗。然而，這項演算法要求全面的非阻塞（Non-blocking），一旦程式發生乾等，整個伺服器引擎就會瞬間癱瘓。這讓我在實務中體會到，網路協議的設計必須與底層多工演算法高度對稱。
3. 資料結構：高效能名冊維護在伺服器端管理動態連線時，專案捨棄了搜尋效率較低、需要線性掃描（O(N)）的線性串列（List），改採用雜湊表（Hash Table）原理的「字典（Dictionary）」結構來維護在線名冊。這使得不論線上人數多寡，伺服器在面對客戶端動態登入（新增）與異常斷線（刪除）時，都能維持 $O(1)$ 的極致查找與操作效率，有效防止了多人同時離線時可能引發的系統卡頓。總結來說，本專案成功將理論課程中抽象的 $O(1)$ 與 $O(N)$ 複雜度分析、多執行緒資源開銷以及 TCP 通訊協議，具體實踐在解決現實網路的效能瓶頸中，達到理論與實務的融會貫通。
